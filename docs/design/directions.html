Three directions for the OpenCode sidebar

Each direction shows the same session, built from what the extension does today: sessions, streaming, tool rows, edit review, context and agent/model choice. Switch the state and sidebar width to compare. Nothing here changes behavior. Approvals stay explicit, untrusted text stays plain, and connection settings stay behind a menu.

State
Sidebar width
A · Native minimal

Looks like the editor's own chat

One-line header, steps as quiet single lines, approvals as an inline confirmation, and selectors inside the input box.

Strengths
  • Feels built in to VS Code and VSCodium, with no new visual language.
  • Least height spent on chrome, so the most conversation fits at 240px.
  • Closest to what the code already does, so it's the cheapest to build.
Trade-offs
  • Long tool runs become a wall of grey lines.
  • The approval box is easy to scroll past in a long reply.
B · Modern restrained · chosen

Conversation first, steps folded

Your messages as soft bubbles, steps grouped into a collapsible block where every step shows its own result, and approvals as a raised card with the file and counts up front.

✓Completed✕FailedRunningQueued!Needs you
Strengths
  • Easiest to read: replies aren't interrupted by tool noise.
  • The approval card is the most noticeable, which suits risky edits.
Trade-offs
  • Bubbles and shadows read less native, especially in high-contrast themes.
  • Folded steps hide what ran unless you open them.
  • Rounded containers cost width at 240px.
C · Dense developer

A log you can scan

Role labels in a gutter, steps as an aligned table with status glyphs and line counts, a one-line approval strip and a status line.

Strengths
  • Shows the most activity per screen, which suits long coding sessions.
  • Agent, model and connection are always visible in the status line.
Trade-offs
  • Small monospace text is harder to read and harder on accessibility.
  • Approval is compact, so it relies on color and placement to stand out.

Chosen: B, with per-step status

Every step shows how it ended, using shape as well as color, so it reads in high-contrast themes and without color vision: ✓ completed, ✕ failed (with a short reason), a spinning ring while running, an empty ring while queued, and ! when it needs you. The block header summarizes the run, and a finished run folds to one line such as "✓ 2 steps · done".

Kept from the other directions:

  • From A: connection settings in a ⋯ menu, the session as the header title, and agent, model and context in the composer toolbar.
  • From C: finished step runs collapse to a single summary line.

Before shipping, B gets these adjustments for the editor:

  1. In high-contrast themes, shadows and fills are replaced by the theme's contrast borders.
  2. Below 260px wide, corner radii and side padding shrink so the bubbles and cards don't waste width.
  3. Steps stay expandable to show their full output as plain text, as they do today.
